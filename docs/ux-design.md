# Plan UX 设计方案

## 1. 文档目标

本文档基于 `/home/tianci/plan/api/docs/architecture.md`，为 `Plan` 首版产品定义可落地的 UX 方案。目标不是做一套偏概念化的视觉提案，而是明确：

- V1 面向谁解决什么问题
- 用户如何在系统中完成核心任务流转
- 页面和信息结构应该如何组织
- 关键交互、状态反馈、异常处理如何定义
- 后续前端实现时应优先保障哪些体验原则

`Plan` 的 UX 基线应借鉴 `vibe-kanban` 的高效任务流转体验，但保持更轻、更聚焦、更容易维护。

## 2. 产品定位

### 2.1 产品一句话

`Plan` 是一个面向个人开发者和小团队的本地任务管理系统，用最短路径完成“记录任务、安排状态、推进执行、查看细节”。

### 2.2 UX 目标

- 让用户在 10 秒内理解当前项目状态
- 让用户在 3 步内创建并归类一个任务
- 让任务状态流转尽量通过拖拽完成，而不是跳转页面
- 让任务详情编辑始终保留上下文，不打断看板浏览
- 让系统在空状态、失败状态、首次使用时仍然清晰可操作

### 2.3 首版体验边界

V1 只打透一条主链路：

- 进入项目
- 浏览看板
- 创建任务
- 拖拽改状态和顺序
- 打开右侧详情
- 编辑任务信息
- 搜索和筛选任务

V1 不承担以下 UX 负担：

- 多组织切换
- 多人实时协作
- PR、代码评审、工作区联动
- 自动化流程编排
- 复杂权限和审批

## 3. 目标用户与使用场景

### 3.1 核心用户

#### 用户 A：个人开发者

特征：

- 本地开发为主
- 任务量中等
- 需要快速记录想法、安排优先级、跟踪进展

核心诉求：

- 不想配置复杂系统
- 希望看板足够直观
- 任务详情不要太重

#### 用户 B：2 到 8 人的小团队

特征：

- 需要共享同一项目视图
- 关心任务当前阶段和截止时间
- 希望用低成本方式做日常协作

核心诉求：

- 看板状态清楚
- 创建和移动任务足够快
- 搜索、筛选和标签能帮助定位任务

### 3.2 典型场景

- 产品或开发在需求讨论后快速记一批任务
- 每天打开项目页查看哪些任务在进行中、哪些已阻塞
- 执行中通过拖拽调整状态，而不是进入编辑页反复改字段
- 在右侧详情面板补充说明、日期、标签和评论
- 在任务增多后用关键词、标签、优先级快速定位任务

## 4. 体验原则

### 4.1 上下文不丢失

任务详情采用右侧面板，而不是全页跳转。用户查看或编辑一个任务时，主看板仍然可见，方便持续理解任务所在列和整体进展。

### 4.2 快速输入优先

高频动作优先走轻量交互：

- 快速创建任务
- 卡片直接展示关键字段
- 拖拽完成状态流转
- 面板内分区编辑，而不是冗长表单

### 4.3 信息分层清楚

界面按“全局、列、卡片、详情”四层组织：

- 全局层：项目、搜索、筛选、创建按钮
- 列层：状态、任务数量、列操作
- 卡片层：任务摘要
- 详情层：完整编辑和讨论

### 4.4 默认简单，逐步展开

首屏只展示完成主任务所需的信息。次要能力通过折叠区、二级操作或面板展开露出，避免 V1 过早信息过载。

### 4.5 状态反馈明确

每个写操作都必须给出结果反馈：

- 保存成功
- 保存失败
- 拖拽已同步
- 数据加载中
- 没有结果

用户不能依赖猜测判断系统是否生效。

## 5. 信息架构

### 5.1 页面结构

- `/`
  - 项目列表页
  - 无项目时进入创建引导
- `/projects/[projectId]`
  - 项目看板主页面
- `/projects/[projectId]?taskId=xxx`
  - 选中任务并打开右侧详情

### 5.2 主导航结构

V1 不做复杂侧边导航，采用轻量全局框架：

- 左上：产品标识 / 返回项目列表
- 顶部主区域：项目名、搜索、筛选、创建任务
- 中部：看板列横向区域
- 右侧：任务详情面板，仅在选中任务时出现

### 5.3 信息层级

#### 全局级

- 当前项目名称
- 项目描述或简短摘要
- 搜索关键词
- 当前筛选条件
- 新建任务入口

#### 列级

- 列名称
- 列颜色
- 列内任务数
- 是否为完成列

#### 卡片级

- 任务标题
- 标签
- 优先级
- 截止日期
- 评论数或说明存在感知

#### 详情级

- 标题
- 描述
- 状态
- 优先级
- 时间字段
- 标签
- 评论
- 归档或删除动作

## 6. 核心用户流

### 6.1 首次进入系统

目标：帮助用户快速完成第一次有效使用。

流程：

1. 进入项目列表页
2. 页面说明产品用途和核心能力
3. 主按钮为“创建项目”
4. 创建项目后自动生成默认状态列
5. 自动跳转到项目看板
6. 首次进入看板时提示“创建第一个任务”

默认建议状态列：

- 待处理
- 进行中
- 已完成

这样可以降低第一次使用成本，也符合绝大多数任务管理习惯。

### 6.2 快速创建任务

目标：最短路径完成记录。

推荐流程：

1. 用户点击顶部“新建任务”
2. 打开轻量创建面板或弹层
3. 默认只要求输入标题
4. 可选填写状态、优先级、截止日期、标签
5. 提交成功后：
   - 卡片立即插入目标列顶部或尾部
   - 自动高亮新任务 2 秒
   - 可选择继续补充详情

UX 要点：

- 默认焦点落在标题输入框
- 支持回车提交
- 支持 `Esc` 关闭
- 若标题为空，直接在输入框下提示，不用全局弹错

### 6.3 浏览和理解看板

目标：用户快速知道“现在有什么、在哪一列、优先做什么”。

看板卡片默认展示字段：

- 标题
- 1 到 3 个标签
- 优先级标识
- 截止日期
- 评论数量或描述标识

列头展示：

- 状态名
- 数量
- 颜色标识

扫描逻辑应满足：

- 先看列分布，理解流程阶段
- 再看卡片密度，感知工作量
- 最后看卡片摘要，定位具体任务

### 6.4 拖拽任务流转

目标：把状态更新变成最顺手的动作。

行为规则：

1. 用户拖起卡片时，卡片提升层级并保留阴影
2. 目标列出现可放置反馈
3. 放下后先本地乐观更新
4. 同步成功则结束
5. 失败则回滚，并给出明确错误提示

体验要求：

- 拖拽预览必须稳定，不闪烁
- 目标位置要有明显插槽提示
- 跨列时列头高亮，帮助感知状态切换
- 移动到完成列时，可在卡片上即时显示完成状态变化

### 6.5 查看和编辑任务详情

目标：在不离开看板上下文的情况下完成编辑。

打开方式：

- 点击卡片
- 更新 URL 中的 `taskId`
- 右侧面板滑入

面板信息结构：

1. 顶部区
   - 标题
   - 当前状态
   - 关闭按钮
   - 更多操作
2. 基础信息区
   - 描述
   - 优先级
   - 标签
   - 开始日期 / 截止日期
3. 讨论区
   - 评论列表
   - 评论输入框
4. 危险操作区
   - 归档
   - 删除

保存策略：

- V1 建议显式保存
- 字段变更后显示“有未保存更改”
- 主操作按钮固定为“保存更改”
- 关闭面板前若有未保存内容，弹出确认提示

### 6.6 搜索与筛选

目标：在任务增长后仍然保持可控。

搜索区放在顶部工具栏，筛选紧邻搜索框。

首版支持：

- 关键词搜索
- 按状态筛选
- 按优先级筛选
- 按标签筛选
- 是否包含已归档任务

筛选展示原则：

- 当前激活的筛选条件必须可见
- 每个条件可单独移除
- 提供“一键清空筛选”

建议结果反馈：

- 无结果时说明是“没有匹配任务”，不是“系统异常”
- 显示当前关键词和筛选条件，便于用户修正

## 7. 页面与模块方案

### 7.1 项目列表页

页面目标：

- 展示用户已有项目
- 引导创建新项目
- 在无数据时给出首次启动路径

页面结构：

- 顶部：页面标题、创建项目按钮
- 主体：
  - 有项目时使用卡片列表
  - 无项目时使用空状态引导

项目卡片字段：

- 项目名称
- 描述
- 项目颜色
- 最近更新时间
- 任务概览摘要

空状态文案方向：

- 说明可以创建项目来管理任务
- 提供明确的主行动按钮
- 不使用过度营销式语言

### 7.2 项目看板页

页面目标：

- 成为用户的日常主工作界面

推荐布局：

- 顶部固定工具栏
- 中部为横向滚动看板
- 右侧任务详情按需出现

顶部工具栏包含：

- 返回项目列表
- 项目名称和简短说明
- 搜索框
- 筛选器
- 新建任务按钮

看板区要求：

- 列宽固定在适中范围，便于并排扫描
- 列可横向滚动
- 卡片间距统一
- 保持足够留白，避免信息拥挤

### 7.3 任务卡片

卡片应该优先服务“扫读”，而不是承载所有信息。

建议结构：

- 第一行：标题
- 第二行：标签
- 第三行：优先级、截止日期、评论数

交互：

- 整卡可点击打开详情
- 支持拖拽
- Hover 时显示轻微强调，不出现复杂操作堆叠

不建议在卡片上放过多按钮，否则会破坏拖拽和点击的稳定性。

### 7.4 任务详情面板

详情面板宽度应保证可编辑性，但不能压缩主看板到失真。

建议：

- 桌面端固定中等宽度
- 在窄屏下改为全屏抽屉

编辑体验要求：

- 字段顺序与用户思考顺序一致
- 可编辑组件尽量就地展示
- 长描述支持多行编辑
- 标签选择支持搜索和快速创建

### 7.5 评论区

评论是次高频模块，应保证足够轻量。

交互建议：

- 评论按时间正序展示
- 新评论输入框默认固定在评论区底部
- 提交后立即出现在列表中
- 编辑和删除只在对应评论 hover 或聚焦时出现

### 7.6 标签与筛选器

标签系统应兼顾识别性和轻量管理。

规则：

- 标签色彩以区分为主，不作为唯一语义载体
- 标签名称要短
- 项目级统一维护，避免重复创建
- 任务编辑时可直接选已有标签

## 8. 交互细节规范

### 8.1 顶部搜索框

- 占据稳定位置，不随页面内容跳动
- 支持输入后延迟触发搜索
- 输入后显示清空按钮
- 占位文案明确说明可搜标题和描述

### 8.2 筛选交互

- 使用按钮加下拉面板组合
- 面板内按分类展示筛选项
- 应在触发器上显示已激活数量

### 8.3 保存反馈

- 成功：短暂 toast 或字段旁提示
- 失败：明确说明失败原因并保留输入内容
- 保存中：按钮进入 loading，不阻断页面其他阅读操作

### 8.4 删除与归档

V1 主推归档，弱化硬删除。

规则：

- 删除按钮放入危险区
- 删除前二次确认
- 归档优先提供，并解释归档后可恢复

### 8.5 URL 状态

`taskId` 应作为可分享、可恢复的界面状态。

这意味着：

- 刷新后仍能打开同一任务
- 前进后退可恢复面板状态
- 链接可以直接定位到具体任务

## 9. 视觉与界面风格方向

### 9.1 总体风格

`Plan` 的视觉风格应服务“清晰、专注、可信”。

关键词：

- 清爽
- 有秩序
- 本地工具感
- 少装饰，强层次

### 9.2 视觉层级

- 页面背景低对比，避免过重干扰
- 看板列与卡片通过层级差异区分，不依赖粗重边框
- 重点动作用单一主色强调
- 状态色用于辅助识别，不用于堆满界面

### 9.3 字体与密度

- 字体以高可读性为优先
- 默认密度偏紧凑，但必须保留点击热区
- 标题与正文层级差异明确

### 9.4 颜色建议

- 项目级主色：用于强调创建、选中、主操作
- 状态色：用于列头和状态标签
- 风险色：仅用于删除、错误等危险动作

不建议：

- 使用大面积高饱和颜色
- 每个标签都用强烈颜色
- 把优先级、状态、标签都做成同等视觉权重

## 10. 空状态、异常状态与边界情况

### 10.1 无项目

应展示：

- 产品用途说明
- 创建项目按钮
- 简洁的首次使用提示

### 10.2 项目无任务

应展示：

- 当前项目名称
- 对看板用途的简短说明
- “创建第一个任务”主按钮

### 10.3 搜索无结果

应展示：

- 未找到匹配任务
- 当前关键词或筛选条件
- 清空筛选入口

### 10.4 加载中

原则：

- 首屏使用骨架屏，不用纯转圈占满页面
- 详情面板加载时保留面板框架，只加载内容区

### 10.5 保存失败

原则：

- 保留用户已编辑内容
- 指出失败动作和原因
- 提供重试入口

### 10.6 拖拽失败

原则：

- 自动回滚到原位置
- 提示“排序未保存”
- 不让用户自己判断当前顺序是否可信

## 11. 响应式策略

### 11.1 桌面端

这是 V1 主场景，应优先优化。

要求：

- 看板横向可视列数足够
- 详情面板与看板并存
- 搜索与筛选常驻顶部

### 11.2 平板端

策略：

- 保持看板为主
- 详情面板可覆盖式出现
- 工具栏组件适度压缩

### 11.3 手机端

V1 不追求完整桌面等价体验，但要可用。

建议：

- 顶部工具栏改为两行或折叠
- 看板横向滚动继续保留
- 详情面板改全屏抽屉
- 减少同时出现的信息密度

## 12. 可访问性要求

### 12.1 键盘操作

至少支持：

- `Tab` 在主操作间移动
- `Enter` 提交创建任务
- `Esc` 关闭弹层或面板
- 焦点状态清晰可见

### 12.2 颜色对比

- 文字与背景对比满足基本可读性
- 状态和标签不能只靠颜色区分

### 12.3 屏幕阅读器

重点区域应具备清晰语义：

- 看板列标题
- 任务卡片可点击状态
- 详情面板标题
- 保存反馈与错误提示

### 12.4 拖拽替代方案

考虑到键盘和辅助技术用户，后续应补充非拖拽方案，例如在详情面板或卡片菜单中直接修改状态。

## 13. 文案原则

### 13.1 文案风格

- 直接
- 短句
- 不营销
- 动作导向

### 13.2 文案示例方向

- “新建任务”
- “保存更改”
- “添加评论”
- “清空筛选”
- “归档任务”

避免：

- 含糊表达，如“提交一下”
- 情绪化表达，如“太棒了，你完成了”
- 技术化报错直接裸露给用户

## 14. 实现优先级建议

### 14.1 P0

- 项目列表页
- 项目看板页
- 任务快速创建
- 任务卡片
- 右侧详情面板
- 拖拽排序
- 空状态和基础错误反馈

### 14.2 P1

- 标签管理
- 评论区
- 搜索与筛选
- 归档视图或归档入口

### 14.3 P2

- 活动日志
- 子任务
- 任务关系
- 更多批量操作

## 15. 验收标准

如果 V1 UX 方案落地正确，用户应能做到：

- 第一次进入系统后 1 分钟内创建项目并创建首个任务
- 在看板中不经过页面跳转完成任务浏览、创建、拖拽、编辑
- 在任务量增加后通过搜索和筛选快速找到目标任务
- 在保存失败或拖拽失败时明确知道发生了什么，并知道下一步该做什么

## 16. 最终结论

`Plan` 的 UX 核心不是功能堆叠，而是把任务管理最常用的一条链路做到足够顺畅：

- 看板负责理解全局
- 卡片负责快速扫读
- 详情面板负责完整编辑
